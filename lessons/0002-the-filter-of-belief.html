The Filter of Belief

Lesson 0002 · ~12 minutes · Conditional probability — the doorway to Bayes

You've just learned something. Maybe you rolled one die and saw it's odd, or you heard that it rained in the morning, or a test came back positive. New information changes what you should believe about other things.

This lesson is about what "changing your beliefs" means precisely — and it turns out to be the most familiar thing in programming: .filter().

1 · Conditioning = restricting Ω

When you learn that event B occurred, you don't throw away your model — you just zoom in. Everything outside B becomes impossible. The new universe is B.

In code you've done this a thousand times:

const outcomes = ['HH','HT','TH','TT'];          // Ω — the full sample space

// You learn coin₁ was Heads. That's event B:
const B = outcomes.filter(ω => ω[0] === 'H');    // ['HH','HT']  ← new universe

// Now ask: given B, what's P(both heads)?
const A = ['HH'];
const AgivenB = B.filter(ω => A.includes(ω));    // ['HH']

const P_A_given_B = AgivenB.length / B.length;   // 1/2

That's it. Conditional probability is filter, then count. The math just gives it a compact notation:

P(A | B)  ("probability of A given B")
Plain language: assuming B already happened, what fraction of B's outcomes also satisfy A? The pipe | means exactly what it means in a SQL WHERE clause or a Unix pipe — "filter to this".
const P = (A: ω[], B: ω[]) => B.filter(ω => A.includes(ω)).length / B.length;
// P(A | B): filter Ω down to B, then count how much of B is in A

2 · The intersection: A and B both occurring

Notice that B.filter(ω => A.includes(ω)) selects outcomes that are in both A and B. That region has its own name and symbol:

A ∩ B  ("A intersect B" — A and B)
Plain language: the set of outcomes where both A and B occur. The symbol ∩ looks like an upside-down ∪ — think of it as a net catching only what falls in both buckets.
const intersect = (A: Set<ω>, B: Set<ω>) => [...A].filter(x => B.has(x)); // A ∩ B

With this in hand, the conditional probability formula writes itself. P(A|B) is just "the fraction of B that is also in A" — which is P(A∩B) divided by P(B):

🏆 Trophy Formula № 2
P(A | B) = P(A ∩ B) P(B)
In code: intersect(A,B).length / B.length — filter to B, measure A inside it. Valid whenever P(B) > 0 (you can't condition on the impossible).
Why divide by P(B)? You're rescaling. After filtering to B, B is the new 100% — so you normalize by P(B) to make the probabilities sum to 1 again. Same reason you divide by B.length, not outcomes.length, after filtering.

Unconditioned: Ω is the whole box, and A∩B (dark blue) is whatever sliver of it satisfies both events.

Nothing about A or B changed shape or size when you clicked. The only thing that changed is which box counts as 100%. That rescaling — old Ω to new B — is the entire content of dividing by P(B) in the trophy formula above: same dark region, smaller denominator.

A & B  (TypeScript's intersection type — the same ∩)
Plain language: when A and B are unions of literal outcomes, TypeScript's & operator computes exactly A∩B — it distributes over the union and keeps only the literals both types share, discarding the rest as never.
type A = 'HH' | 'HT' | 'TH'; // event A
type B = 'HH' | 'HT'; // event B
type AandB = A & B; // resolves to 'HH' | 'HT' — literally A ∩ B
This is the same lens Type-Level TypeScript uses for the whole type system: a type is a set of values, | is union, & is intersection, and narrowing (if, as, discriminated unions) is exactly what you just watched the diagram do above — shrinking the universe down to a subset once you learn something is true.

5 · Why this matters for decisions

Here's where conditional probability becomes a superpower. Suppose you take a medical test for a rare disease. The test comes back positive. Should you panic?

Your gut says yes — "the test is positive." But your gut is ignoring the Ω shrinkage. The right question is: given a positive test result (event B), what fraction of those people actually have the disease (event A)? That's P(disease | positive test) — and it depends critically on how rare the disease is in the first place.

This is the base-rate trap, and it bites doctors, judges, and investors constantly. Working it out precisely requires one more algebraic step — and that step is Bayes' theorem. That's Lesson 3.

The punchline: even a 99%-accurate test can give a mostly-false positive rate if the disease is rare enough. We'll compute the exact number in Lesson 3 and it will surprise you.
