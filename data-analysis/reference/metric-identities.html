The Metric Identity Tree

Four counters. Everything else is a ratio. Print this.

The counters

V = Visits ──▶ O = Orders ──▶ U = Units ──▶ D = Demand ($)
  (sessions)     (checkouts)     (items)      (dollars)

The acronyms, letter by letter

CVR  ConVersion Rate          AOV  Average Order Value
UPT  Units Per Transaction    AUR  Average Unit Retail
RPV  Revenue Per Visit

The tree

          D      O     D
RPV  ≡   ───  = ─── · ───   =  CVR · AOV        O cancels — exact algebra
          V      V     O
Revenue Per Visit ≡ ConVersion Rate × Average Order Value
                             │
                             ├─  U/O  =  UPT   units per transaction (basket size)
                             └─  D/U  =  AUR   average unit retail (item price)

RPV ≡ CVR · UPT · AUR              the full decomposition
Revenue Per Visit ≡ ConVersion Rate × Units Per Transaction × Average Unit Retail

Lift (ℓ)

ℓ = T/C − 1                      e.g. 3.6% / 3.0% − 1 = +20%
lift = test ÷ control − 1

lifts compound multiplicatively through the tree:
(1 + ℓRPV) = (1 + ℓCVR) · (1 + ℓAOV)
(1 + Revenue-Per-Visit lift) = (1 + ConVersion-Rate lift) × (1 + Average-Order-Value lift)

The decomposition recipe (move #1 on any RPV claim)

  1. Compute CVR lift and AOV lift for the same period.
  2. Whichever leg moved is where the story lives — the ledger always closes.
  3. If AOV moved: split into UPT vs AUR, then check order counts — at <50 orders/arm suspect a whale before a cause.
  4. If CVR moved: check the upstream funnel gate (cart-add rate) — a real behavioral cause must pass through it.

Which leg can a cause even reach?

Claimed causeLegs it can touchLegs it cannot
Page speed / latencyCVR (via funnel exits)AOV, UPT, AUR
Recommendation modelCVR, UPT, AUR— (all reachable)
Pricing / promosAUR, CVR—
A whale orderAOV (as noise)CVR

A cause with no path to the moved leg is not the cause. This one row-lookup killed the "latency cost us revenue" story: the moved leg was AOV, which latency cannot reach.

Trap Never diagnose from RPV directly — it inherits the noise of both legs and is the least readable series on the dashboard. Decompose first, always.
